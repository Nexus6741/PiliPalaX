# 话题标签显示逻辑说明

## 核心逻辑

动态中的话题标签分为两种类型，显示方式和跳转行为不同。

## 两种类型

### 1. 真正的话题（有话题 ID）

**判断条件**：
- 有 `rid` 字段（话题 ID）
- `rid` 不为空

**显示方式**：
```
🔖 话题名称
```
- 显示小电视图标
- 话题名称不包含 `#`
- 使用主题色

**点击行为**：
- 跳转到话题页面（`/dynamicsTopic`）
- 传递参数：`id`（话题 ID）、`name`（话题名称）

**示例**：
```
原始数据：#年末总结#
显示效果：🔖 年末总结
点击跳转：话题页面
```

### 2. 普通标签（无话题 ID）

**判断条件**：
- 没有 `rid` 字段
- 或 `rid` 为空

**显示方式**：
```
#标签名#
```
- 不显示小电视图标
- 保持原始文本（包含 `#`）
- 使用主题色

**点击行为**：
- 跳转到搜索页面（`/searchResult`）
- 传递参数：`keyword`（标签名称，去掉 `#`）

**示例**：
```
原始数据：#标签名#
显示效果：#标签名#
点击跳转：搜索页面
```

## 实现位置

### 动态顶部话题
**文件**：`lib/pages/dynamics/widgets/content_panel.dart`

**特点**：
- 始终是真正的话题（有话题 ID）
- 始终显示小电视图标
- 始终跳转到话题页面

**代码**：
```dart
if (widget.item.modules.moduleDynamic.topic != null) {
  // 显示小电视图标 + 话题名称
  // 点击跳转到话题页面
}
```

### 富文本中的话题
**文件**：`lib/pages/dynamics/widgets/rich_node_panel.dart`

**特点**：
- 可能是真正的话题，也可能是普通标签
- 根据 `rid` 判断类型
- 显示方式和跳转行为不同

**代码**：
```dart
if (i.type == 'RICH_TEXT_NODE_TYPE_TOPIC') {
  final bool isRealTopic = i.rid != null && i.rid!.isNotEmpty;
  
  if (isRealTopic) {
    // 显示小电视图标
    // 显示话题名称（无 #）
    // 点击跳转到话题页面
  } else {
    // 不显示图标
    // 显示原始文本（含 #）
    // 点击跳转到搜索页面
  }
}
```

## 数据结构

### 真正的话题
```json
{
  "type": "RICH_TEXT_NODE_TYPE_TOPIC",
  "origText": "#年末总结#",
  "text": "年末总结",
  "rid": "12345"  // 有话题 ID
}
```

### 普通标签
```json
{
  "type": "RICH_TEXT_NODE_TYPE_TOPIC",
  "origText": "#标签名#",
  "text": "标签名",
  "rid": null  // 无话题 ID
}
```

## 用户体验

### 视觉区分
- 用户可以通过图标区分话题和标签
- 小电视图标 = 可以进入话题页面
- `#` 符号 = 搜索标签

### 交互一致性
- 真正的话题：提供完整的话题体验（详情、动态列表、点赞收藏等）
- 普通标签：提供搜索功能（查找相关内容）

### 降级策略
- 如果话题数据不完整（无 ID），自动降级为搜索
- 保证功能始终可用

## 对比 PiliPlus

### 相同点
- 使用相同的小电视图标
- 相同的颜色方案
- 相同的布局和间距

### 差异点
- **PiliPlus**：富文本中的话题标签统一跳转到搜索页
- **我们的实现**：根据是否有话题 ID 智能选择跳转目标
  - 有 ID：跳转到话题页面（更好的体验）
  - 无 ID：跳转到搜索页面（降级方案）

### 优势
- 更智能的跳转逻辑
- 更好的用户体验
- 充分利用话题页面功能

## 常见问题

### Q1：如何判断是否为真正的话题？
A：检查 `rid` 字段是否存在且不为空。

### Q2：为什么要区分两种类型？
A：提供更好的用户体验。真正的话题有完整的话题页面，普通标签只能搜索。

### Q3：如果话题 ID 无效怎么办？
A：会跳转到话题页面，由话题页面处理错误（显示错误信息或空状态）。

### Q4：普通标签为什么不去掉 `#`？
A：保持原始样式，让用户知道这是一个标签而不是话题。
