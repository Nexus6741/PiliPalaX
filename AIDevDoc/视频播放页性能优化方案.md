# 视频播放页性能优化方案

## 问题现象
从卡片点击进入视频播放页，或在播放器中点击相关视频跳转时，偶发出现约 0.8s 的画面卡顿。

## 性能瓶颈分析

### 1. 页面初始化延迟过长 ⚠️ 高优先级
**位置**: `lib/pages/video/view.dart` - `initState()`

```dart
// 当前实现
Future.delayed(const Duration(milliseconds: 400), () {
  videoSourceInit();
  setState(() {
    _playerInitFinished = true;
    _playerOpacity = 1.0;
  });
})
```

**问题**:
- 硬编码 400ms 延迟，等待 Hero 动画完成
- 然后又有 50ms + 50ms 延迟初始化简介和评论
- 总计 500ms 的人为延迟

**优化方案**:
- 使用 `WidgetsBinding.instance.addPostFrameCallback` 替代固定延迟
- 监听 Hero 动画完成事件，而不是猜测时间
- 并行初始化简介和评论，而不是串行

### 2. 封面图片重复渲染 ⚠️ 高优先级
**位置**: `lib/pages/video/view.dart` - `childWhenDisabled`

**问题**:
- VideoHero 中的封面
- 播放器加载时的封面淡出动画
- 手动播放模式的封面
- 每个都创建独立的 NetworkImgLayer，没有复用

**优化方案**:
- 提取封面为单独的 Widget，使用 RepaintBoundary 隔离
- 使用 ValueKey 确保图片缓存复用
- 减少封面渲染层级

### 3. 透明度动画嵌套 ⚠️ 中优先级
**位置**: `lib/pages/video/view.dart` - 播放器渲染部分

**问题**:
```dart
if (_playerOpacity > 0)
  Opacity(
    opacity: _playerOpacity,
    child: plPlayer,  // 内部又有 AnimatedOpacity
  ),
```

**优化方案**:
- 移除外层 Opacity，直接使用内部的 AnimatedOpacity
- 或者合并为单一的透明度控制

### 4. Obx 过度使用 ⚠️ 中优先级
**位置**: 整个 `view.dart` 文件

**问题**:
- 大量 Obx 监听器，每个都会触发重建
- 某些 Obx 监听的值变化频繁（如播放进度）

**优化方案**:
- 合并相关的 Obx，减少监听器数量
- 使用 GetBuilder 替代不需要细粒度更新的 Obx
- 为频繁变化的值添加节流

### 5. didPopNext 重复初始化 ⚠️ 高优先级
**位置**: `lib/pages/video/view.dart` - `didPopNext()`

**问题**:
```dart
Future.delayed(const Duration(milliseconds: 400), () {
  videoDetailController.playerInit(autoplay: ...);
  // 重新初始化播放器
});
```

**优化方案**:
- 保持播放器实例，只更新数据源
- 使用播放器的 `setMedia` 方法切换视频，而不是重建
- 减少不必要的 controller 重建

### 6. 播放器初始化时机 ⚠️ 高优先级
**位置**: `lib/pages/video/view.dart` - `videoSourceInit()`

**问题**:
- 等待 Hero 动画完成后才开始请求视频 URL
- 网络请求和播放器初始化都在主线程

**优化方案**:
- 提前预加载视频 URL（在卡片点击时）
- 使用 Isolate 处理视频数据解析
- 播放器初始化与 Hero 动画并行

### 7. 多个 AnimatedContainer ⚠️ 低优先级
**位置**: `lib/pages/video/view.dart` - 视频容器

**问题**:
- AnimatedContainer 会在每次尺寸变化时重建子树
- 350ms 的动画时长可能与其他动画冲突

**优化方案**:
- 使用 AnimatedSize 或 SizeTransition 替代
- 减少动画时长到 250ms
- 添加 `clipBehavior: Clip.none` 避免裁剪开销

## 优化实施计划

### 阶段一：快速优化（预计提升 40-50%）
1. ✅ 移除 EnhancedHero 的复杂动画效果（已完成）
2. 减少页面初始化延迟（400ms -> 200ms）
3. 优化封面图片渲染（复用 + RepaintBoundary）
4. 移除透明度嵌套

### 阶段二：深度优化（预计提升 30-40%）
1. 优化 didPopNext 的播放器重建逻辑
2. 提前预加载视频 URL
3. 合并和减少 Obx 监听器
4. 添加性能监控点

### 阶段三：架构优化（预计提升 10-20%）
1. 播放器实例池化，避免重复创建
2. 视频数据解析移到 Isolate
3. 实现渐进式页面加载
4. 优化 GetX 依赖注入

## 预期效果

- **当前**: 偶发 0.8s 卡顿
- **阶段一后**: 减少到 0.3-0.4s
- **阶段二后**: 减少到 0.1-0.2s
- **阶段三后**: 基本无感知卡顿

## 测试验证

### 性能指标
- Hero 动画帧率：目标 60fps
- 页面初始化时间：目标 < 300ms
- 播放器就绪时间：目标 < 500ms
- 内存占用：目标 < 150MB

### 测试场景
1. 首页卡片 -> 视频播放页
2. 播放页 -> 相关视频 -> 返回
3. 播放页 -> 相关视频 -> 再次跳转
4. 快速连续点击多个视频

## 注意事项

1. 优化后需要在多种设备上测试（低端、中端、高端）
2. 注意 iOS 和 Android 的差异
3. 监控内存泄漏问题
4. 保持代码可维护性
