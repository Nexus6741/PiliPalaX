  if (entry.isCompleted) {

      '/video',
      parameters: {
        'bvid': entry.bvid,

        'entry': entry,
        'dirPath': entry.entryDirPath,

### 3. 修改视频控制器 - 支持本地文件

**文件**: `lib/pages/video/controller.dart`

在 `queryVideoUrl()` 方法中添加本地文件播放逻辑：

```dart
Future queryVideoUrl() async {
  // 检查是否是离线播放
  if (Get.arguments != null && Get.arguments['sourceType'] == SourceType.file) {
    final entry = Get.arguments['entry'] as DownloadEntryInfo;
    final dirPath = Get.arguments['dirPath'] as String;
    
    // 构建本地文件路径
    final videoDir = Directory(path.join(dirPath, entry.typeTag!));
    final mediaJsonFile = File(path.join(videoDir.path, 'index.json'));
    
    if (mediaJsonFile.existsSync()) {
      final mediaJson = jsonDecode(await mediaJsonFile.readAsString());
      final mediaInfo = DownloadMediaInfo.fromJson(mediaJson);
      
      // 根据媒体类型构建播放地址
      if (mediaInfo is Type1MediaInfo) {
        // FLV 格式
        final videoFile = File(path.join(videoDir.path, 'video.flv'));
        if (videoFile.existsSync()) {
          videoUrl.value = videoFile.path;  // 使用本地文件路径
        }
      } else if (mediaInfo is Type2MediaInfo) {
        // DASH 格式
        final videoFile = File(path.join(videoDir.path, 'video.m4s'));
        final audioFile = File(path.join(videoDir.path, 'audio.m4s'));
        
        if (videoFile.existsSync()) {
          videoUrl.value = videoFile.path;
          if (audioFile.existsSync()) {
            audioUrl.value = audioFile.path;
          }
        }
      }
      
      // 加载本地弹幕
      await loadLocalDanmaku(dirPath);
      return;
    }
  }
  
  // 原有的在线播放逻辑
  // ...
}
```

## 简化实现方案（推荐）

由于完整实现比较复杂，建议先实现一个简化版本：

### 方案A：直接跳转到在线播放

最简单的方式是点击下载项后，直接跳转到该视频的在线播放页面：

```dart
onTap: () {
  Get.toNamed(
    '/video',
    parameters: {
      'bvid': entry.bvid,
      'cid': entry.cid.toString(),
    },
  );
}
```

**优点**: 实现简单，无需修改播放器
**缺点**: 需要网络，不是真正的离线播放

### 方案B：使用 file:// 协议播放

media_kit 播放器支持直接播放本地文件：

1. 在下载页面点击时传递本地文件路径
2. 视频控制器检测到本地路径后，直接使用 `file://` 协议播放
3. 弹幕从本地 protobuf 文件加载

**优点**: 真正的离线播放
**缺点**: 需要处理 DASH 格式的音视频合并

## 当前建议

**第一步**: 先实现方案A，让用户可以点击下载项跳转到视频页面

**第二步**: 再逐步实现方案B的完整离线播放功能

## 技术难点

1. **DASH 格式处理**: 视频和音频分离，需要合并或同时播放
2. **弹幕加载**: protobuf 格式解析
3. **进度记录**: 离线播放的进度需要单独记录
4. **封面显示**: 使用本地封面文件
