# 缓存暂停和跳过功能修复完成

## 问题描述

用户反馈缓存功能存在严重问题：

1. **暂停功能失效**：点击暂停按钮没有反应
2. **卡住无法处理**：第一个视频卡住后，无法删除也无法暂停
3. **队列阻塞**：后面的视频无法继续缓存，整个队列被阻塞

## 根本原因分析

### 1. 错误处理不完整

**问题代码 - `_onDone()`**：
```dart
void _onDone([Object? error]) {
  if (error != null) {
    entry.status.value = videoManager?.status ?? DownloadStatus.pause;
    if (entry.status.value != DownloadStatus.pause) {
      waitDownloadQueue.remove(entry);
    }
    return;  // ❌ 没有清理状态，没有启动下一个下载
  }
  // ...
}
```

**问题**：
- 出现错误时只是从队列移除，但没有清理 `_curCid`、`curDownload`、`videoManager` 等状态
- 没有调用 `startDownload()` 启动下一个下载
- 导致队列卡住，后续视频无法下载

### 2. 异常处理缺失

**问题代码 - `_startDownload()`**：
```dart
Future<void> _startDownload(DownloadEntryInfo entry) async {
  try {
    if (!await downloadDanmaku(entry: entry)) {
      return;  // ❌ 弹幕失败就直接返回，不下载视频
    }
    // ...
  } catch (e) {
    _updateCurStatus(DownloadStatus.failPlayUrl);
    // ❌ 没有清理状态，没有启动下一个下载
  }
}
```

**问题**：
- 弹幕下载失败就放弃整个下载
- 异常捕获后没有清理状态和启动下一个下载
- 导致当前下载卡住，队列阻塞

### 3. 缺少跳过功能

当视频卡住时，用户没有办法跳过它继续下载下一个视频。

## 解决方案

### 1. 完善错误处理 - `_onDone()`

```dart
void _onDone([Object? error]) {
  final entry = curDownload.value;
  if (entry == null) return;

  if (error != null) {
    entry.status.value = videoManager?.status ?? DownloadStatus.pause;
    // 如果是暂停，保留在队列中；如果是失败，从队列中移除
    if (entry.status.value != DownloadStatus.pause) {
      waitDownloadQueue.remove(entry);
      // ✅ 清理状态
      _curCid = null;
      curDownload.value = null;
      videoManager = null;
      audioManager = null;
      // ✅ 启动下一个下载
      startDownload();
    }
    return;
  }

  // ... 处理成功的情况
  
  if (status == DownloadStatus.failDownload ||
      status == DownloadStatus.failDownloadAudio) {
    waitDownloadQueue.remove(entry);
    // ✅ 清理状态
    _curCid = null;
    curDownload.value = null;
    videoManager = null;
    audioManager = null;
    // ✅ 启动下一个下载
    startDownload();
  }
}
```

**改进**：
- 失败时完整清理所有状态
- 自动启动下一个下载
- 队列不会被阻塞

### 2. 改进异常处理 - `_startDownload()`

```dart
Future<void> _startDownload(DownloadEntryInfo entry) async {
  try {
    // ✅ 弹幕失败不影响视频下载
    if (!await downloadDanmaku(entry: entry)) {
      if (kDebugMode) {
        debugPrint('Failed to download danmaku, but continue with video');
      }
    }

    _updateCurStatus(DownloadStatus.getPlayUrl);
    final DownloadMediaInfo mediaFileInfo = await _getVideoUrl(entry: entry);
    // ... 继续下载视频
    
  } catch (e) {
    _updateCurStatus(DownloadStatus.failPlayUrl);
    if (kDebugMode) {
      debugPrint('get download url error: $e');
    }
    // ✅ 失败后从队列移除并启动下一个
    waitDownloadQueue.remove(entry);
    _curCid = null;
    curDownload.value = null;
    videoManager = null;
    audioManager = null;
    // ✅ 启动下一个下载
    startDownload();
  }
}
```

**改进**：
- 弹幕失败不影响视频下载
- 异常时完整清理状态
- 自动启动下一个下载

### 3. 简化 `startDownload()`

```dart
Future<void> startDownload() {
  return _lock.synchronized(() async {
    if (waitDownloadQueue.isEmpty) {
      return;
    }
    if (curDownload.value != null) {
      return;
    }

    final entry = waitDownloadQueue.first;
    _curCid = entry.cid;
    curDownload.value = entry;

    // ✅ _startDownload 内部会处理异常和启动下一个下载
    await _startDownload(entry);
  });
}
```

**改进**：
- 移除重复的异常处理
- 让 `_startDownload` 内部统一处理

### 4. 新增跳过功能

```dart
/// 跳过当前下载，继续下一个
Future<void> skipCurrentDownload() async {
  final entry = curDownload.value;
  if (entry == null) return;

  // 取消当前下载
  await videoManager?.cancel(isDelete: false);
  await audioManager?.cancel(isDelete: false);

  // 标记为暂停状态
  entry.status.value = DownloadStatus.pause;
  await _updateBiliDownloadEntryJson(entry);

  // 清理状态
  _curCid = null;
  curDownload.value = null;
  videoManager = null;
  audioManager = null;

  // 启动下一个下载
  startDownload();
}
```

**功能**：
- 跳过卡住的下载
- 保留任务（标记为暂停）
- 继续下载下一个视频

## 技术要点

### 1. 状态清理的重要性
每次下载结束（成功、失败、取消）都必须清理：
- `_curCid = null`
- `curDownload.value = null`
- `videoManager = null`
- `audioManager = null`

### 2. 队列管理策略
- **正在下载**：保留在队列中，用 `_curCid` 标记
- **下载完成**：从队列移除，加入已完成列表
- **下载失败**：从队列移除，清理状态
- **暂停**：保留在队列中，清理状态
- **跳过**：标记为暂停，清理状态

### 3. 错误传播
- `_startDownload` 内部处理所有异常
- `startDownload` 不需要额外的 try-catch
- 避免重复的错误处理逻辑
