# 下载队列持久化问题修复完成

## 问题描述
用户反馈：切换视频或退出缓存页面后，进度条会归零，只有重新开始下载才会正常显示。

## 问题分析

### 根本原因
在 `lib/services/download_service.dart` 中，`_onReceive()` 方法只在 `progress == 0 && total != 0` 时保存进度到 JSON，但在下载过程中和暂停时没有持久化进度信息。

### 具体问题
1. **下载过程中**：进度更新频繁（每100ms），但从不保存到磁盘
2. **暂停时**：虽然调用了 `_updateBiliDownloadEntryJson()`，但此时 `totalBytes` 和 `downloadedBytes` 可能还没有最新值
3. **切换视频时**：当前下载被暂停，但进度没有及时保存
4. **退出页面时**：所有暂停的视频进度都没有保存

### 数据流分析
```
下载开始 → _onReceive() 更新内存中的 RxInt
         ↓
         只在 progress==0 时保存一次
         ↓
下载过程中不保存
         ↓
暂停/切换 → cancelDownload() → 保存 JSON
         ↓
但此时可能已经丢失了最新的进度值
```

## 修复方案

### 1. 定期保存进度
在 `_onReceive()` 方法中添加智能保存策略：
- **条件1**：进度变化超过 5MB 时立即保存
- **条件2**：使用定时器，每 5 秒保存一次
- **优化**：避免频繁写入磁盘，使用 Timer 延迟保存

### 2. 暂停时立即保存
在所有暂停操作中确保立即保存进度：
- `cancelDownload()` - 暂停下载
- `prioritizeDownload()` - 切换到其他视频
- `skipCurrentDownload()` - 跳过当前下载
- `_onDone()` - 下载完成或失败

### 3. 清理定时器
在所有状态转换时清理进度保存定时器：
- 下载完成
- 下载失败
- 暂停下载
- 切换视频
- 删除下载

## 代码修改

### 修改文件
`lib/services/download_service.dart`

### 关键修改

#### 1. 添加定时器和进度追踪
```dart
Timer? _progressSaveTimer;
int _lastSavedProgress = 0;
```

#### 2. 改进 _onReceive() 方法
```dart
void _onReceive(int progress, int total) {
  final entry = curDownload.value;
  if (entry != null) {
    // 更新总大小
    if (total != 0 && entry.totalBytes.value != total) {
      entry.totalBytes.value = total;
      _updateBiliDownloadEntryJson(entry);
    }
    
    // 更新已下载大小
    entry.downloadedBytes.value = progress;
    entry.status.value = DownloadStatus.downloading;

    // 每隔5秒或进度变化超过5MB时保存一次进度
    final progressDiff = (progress - _lastSavedProgress).abs();
    if (progressDiff > 5 * 1024 * 1024) {
      _lastSavedProgress = progress;
      _updateBiliDownloadEntryJson(entry);
    } else {
      // 使用定时器延迟保存，避免频繁写入
      _progressSaveTimer?.cancel();
      _progressSaveTimer = Timer(const Duration(seconds: 5), () {
        _lastSavedProgress = progress;
        _updateBiliDownloadEntryJson(entry);
      });
    }

    // 强制刷新UI
    waitDownloadQueue.refresh();
  }
}
```

#### 3. 在所有暂停操作中清理定时器
```dart
// cancelDownload()
_progressSaveTimer?.cancel();
_progressSaveTimer = null;
_lastSavedProgress = 0;

// prioritizeDownload()
_progressSaveTimer?.cancel();
_progressSaveTimer = null;
_lastSavedProgress = 0;

// skipCurrentDownload()
_progressSaveTimer?.cancel();
_progressSaveTimer = null;
_lastSavedProgress = 0;

// _onDone()
_progressSaveTimer?.cancel();
_progressSaveTimer = null;
_lastSavedProgress = 0;

// _completeDownload()
_progressSaveTimer?.cancel();
_progressSaveTimer = null;
_lastSavedProgress = 0;
```

#### 4. 暂停时立即保存进度
```dart
// 在 _onDone() 中，暂停时保存
if (entry.status.value == DownloadStatus.pause) {
  _updateBiliDownloadEntryJson(entry);
}
```

## 技术细节

### 保存策略
1. **立即保存**：
   - 总大小变化时
   - 进度变化超过 5MB 时
   - 暂停/切换/完成时

2. **延迟保存**：
   - 使用 5 秒定时器
   - 避免频繁磁盘写入
   - 每次新的进度更新会重置定时器

### 性能优化
- **减少磁盘 I/O**：不是每次进度更新都保存
- **智能触发**：只在必要时保存（大进度变化或定时）
- **及时清理**：状态转换时清理定时器，避免内存泄漏

### 数据一致性
- **RxInt 响应式**：UI 实时更新
- **JSON 持久化**：定期保存到磁盘
- **状态同步**：暂停时确保 JSON 和内存一致

## 测试场景

### 场景1：下载过程中切换视频
1. 开始下载视频A
2. 等待进度到达 30%
3. 点击视频B的"立即下载"
4. 返回查看视频A的进度
5. **预期**：视频A显示 30% 左右的进度

### 场景2：暂停后退出页面
1. 开始下载视频
2. 等待进度到达 50%
3. 点击暂停
4. 退出缓存页面
5. 重新进入缓存页面
6. **预期**：视频显示 50% 左右的进度

### 场景3：多个视频暂停
1. 添加多个视频到队列
2. 第一个视频下载到 20%，暂停
3. 第二个视频下载到 40%，暂停
4. 退出页面并重新进入
5. **预期**：两个视频都显示正确的进度

### 场景4：应用重启
1. 开始下载视频
2. 等待进度到达 60%
3. 强制关闭应用
4. 重新启动应用
5. 进入缓存页面
6. **预期**：视频显示最后保存的进度（55%-60% 之间）

## 注意事项

1. **定时器清理**：确保在所有状态转换时清理定时器
2. **进度精度**：由于定期保存，可能会丢失最后 5 秒的进度
3. **磁盘写入**：平衡保存频率和性能，避免过度写入
4. **并发安全**：使用 `_lock` 确保状态转换的原子性
