# 快速测试指南 - 进度持久化修复

## 测试目标
验证下载进度在各种场景下都能正确保存和恢复

## 快速测试步骤

### 测试1：切换视频（最常见场景）
```
1. 开始下载视频A
2. 等待进度到 30%
3. 点击视频B的"立即下载"按钮
4. 观察视频A的进度条
✅ 应该显示 30% 左右，不是 0%
```

### 测试2：暂停后退出
```
1. 开始下载视频
2. 等待进度到 50%
3. 点击暂停按钮
4. 返回上一页
5. 重新进入缓存页面
✅ 应该显示 50% 左右，不是 0%
```

### 测试3：多视频暂停
```
1. 添加3个视频到队列
2. 第一个下载到 20%，点击暂停
3. 第二个下载到 40%，点击暂停
4. 第三个下载到 60%，点击暂停
5. 退出并重新进入缓存页面
✅ 三个视频都应该显示正确的进度
```

### 测试4：应用重启（极端场景）
```
1. 开始下载视频
2. 等待进度到 70%
3. 强制关闭应用（不要暂停）
4. 重新启动应用
5. 进入缓存页面
✅ 应该显示 65%-70% 之间的进度
   （可能丢失最后5秒的进度，这是正常的）
```

## 关键改进点

### 1. 智能保存策略
- **大进度变化**：超过 5MB 立即保存
- **定时保存**：每 5 秒保存一次
- **状态变化**：暂停/切换/完成时立即保存

### 2. 性能优化
- 避免每次进度更新都写磁盘
- 使用定时器延迟保存
- 平衡数据安全和性能

### 3. 数据一致性
- UI 实时更新（RxInt）
- 磁盘定期保存（JSON）
- 状态转换时强制同步

## 预期行为

### ✅ 正常情况
- 进度条实时更新
- 切换视频进度保持
- 暂停后进度保持
- 退出页面进度保持

### ⚠️ 可接受的情况
- 应用崩溃可能丢失最后 5 秒进度
- 这是性能和数据安全的平衡

### ❌ 不应该出现
- 进度条归零
- 暂停后进度丢失
- 切换视频进度丢失

## 调试提示

如果进度还是归零，检查：
1. 是否正确调用了 `_updateBiliDownloadEntryJson()`
2. JSON 文件是否正确写入（检查文件修改时间）
3. `totalBytes` 和 `downloadedBytes` 是否正确保存到 JSON
4. 定时器是否被正确清理

## 日志位置
- 下载目录：`应用文档目录/downloads/`
- 每个视频的 JSON：`entry.json`
- 检查 `total_bytes` 和 `downloaded_bytes` 字段

## 完成标准
所有4个测试场景都通过 ✅
