# 4K 视频播放优化 - 实施指南

## 核心发现

✅ **你的项目已经使用 Texture 渲染，不是 PlatformView**
- Android: 使用 `TextureRegistry.SurfaceProducer`
- Flutter: 使用 `Texture` widget
- 性能已经是最优方案

## 4K 卡顿的真正原因

基于代码分析，问题可能在于：

### 1. 缓冲区配置偏小
```dart
// 当前配置 (lib/plugin/pl_player/controller.dart:645)
int bufferSize = setting.get(SettingBoxKey.expandBuffer, defaultValue: false)
    ? (videoType.value == 'live' ? 64 * 1024 * 1024 : 32 * 1024 * 1024)
    : (videoType.value == 'live' ? 16 * 1024 * 1024 : 4 * 1024 * 1024);
```

**问题**：4K 视频码率通常 20-50 Mbps，4MB 缓冲不到 2 秒
**建议**：4K 视频至少需要 64-128MB 缓冲

### 2. 没有针对 4K 的特殊配置
当前代码对所有视频使用相同配置，没有根据分辨率动态调整

### 3. 可能的编码格式选择问题
AV1 编码虽然压缩率高，但解码性能要求极高

## 优化方案（按优先级）

### 方案 1：增加 4K 视频缓冲区（最简单有效）

修改 `lib/plugin/pl_player/controller.dart` 的 `_createVideoController` 方法：

```dart
Future<Player> _createVideoController(
  DataSource dataSource,
  PlaylistMode looping,
  bool enableHA,
  String? hwdec,
  double? width,
  double? height,
) async {
  // ... 现有代码 ...
  
  // 🔥 优化：根据视频分辨率动态调整缓冲区
  int bufferSize;
  bool is4K = (width != null && width >= 3840) || 
              (height != null && height >= 2160);
  
  if (is4K) {
    // 4K 视频使用更大的缓冲区
    bufferSize = 128 * 1024 * 1024;  // 128MB
  } else {
    // 原有逻辑
    bufferSize = setting.get(SettingBoxKey.expandBuffer, defaultValue: false)
        ? (videoType.value == 'live' ? 64 * 1024 * 1024 : 32 * 1024 * 1024)
        : (videoType.value == 'live' ? 16 * 1024 * 1024 : 4 * 1024 * 1024);
  }
  
  Player player = _videoPlayerController ??
      Player(
        configuration: PlayerConfiguration(
          bufferSize: bufferSize,
        ),
      );
  
  var pp = player.platform as NativePlayer;
  
  // 🔥 优化：4K 视频额外配置
  if (is4K) {
    // 增加预读取
    await pp.setProperty("demuxer-max-bytes", "200M");
    await pp.setProperty("demuxer-readahead-secs", "10");
    
    // 允许丢帧以保持流畅
    await pp.setProperty("framedrop", "vo");
    
    // 缓存配置
    await pp.setProperty("cache", "yes");
    await pp.setProperty("cache-secs", "15");
  }
  
  // ... 其余代码保持不变 ...
}
```

### 方案 2：优化硬件解码配置

if (is4K && enableHA) {
  // 4K 视频强制使用 auto-safe 模式
  hwdec = 'auto-safe';
  
  // 指定支持硬解的编码格式

// 解除倍速限制

### 方案 4：修改 playerInit 传递分辨率信息

修改 `lib/pages/video/controller.dart` 的 `playerInit` 方法：

```dart
Future playerInit({
  video,
  audio,
  seekToTime,
  duration,
  bool autoplay = true,
}) async {
  plPlayerController ??= PlPlayerController.getInstance();
  headerControl ??= HeaderControl(
    controller: plPlayerController,
    videoDetailCtr: this,
    heroTag: heroTag,
  );
  
  // 🔥 新增：传递视频分辨率信息
  await plPlayerController!.setDataSource(
    DataSource(
      videoSource: video ?? videoUrl,
      audioSource: audio ?? audioUrl,
      type: DataSourceType.network,
      httpHeaders: {
        'user-agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36',
        'referer': HttpString.baseUrl
      },
    ),
    enableHA: enableHA.value,
    hwdec: hwdec.value,
    seekTo: seekToTime ?? defaultST,
    duration: duration ?? (data.timeLength == null ? null : Duration(milliseconds: data.timeLength!)),
    // 🔥 传递分辨率，用于优化配置
    width: firstVideo.width?.toDouble(),
    height: firstVideo.height?.toDouble(),
    direction: firstVideo.width != null && firstVideo.height != null
        ? ((firstVideo.width! - firstVideo.height!) > 0 ? 'horizontal' : 'vertical')
        : null,
    bvid: bvid,
    cid: cid.value,
    epid: epid,
    seasonId: seasonId,
    enableHeart: enableHeart,
    autoplay: autoplay,
  );
  
  plPlayerController!.headerControl = headerControl;
}
```

## 推荐实施顺序

1. ✅ **先实施方案 1**（增加缓冲区）- 最简单有效
2. ✅ **再实施方案 4**（传递分辨率）- 配合方案 1
3. ⚠️ **测试效果**，如果还卡顿再实施方案 2 和 3

## 预期效果

- 4K 视频缓冲区从 4MB → 128MB（提升 32 倍）
- 预缓冲时间从 <2 秒 → 15 秒
- 减少频繁的网络请求和缓冲
- 更流畅的播放体验

## 注意事项

1. **内存占用**：128MB 缓冲会增加内存使用，但对现代设备影响不大
2. **启动时间**：更大的缓冲可能略微增加初始加载时间
3. **网络环境**：慢速网络下仍可能卡顿，这是网络问题而非播放器问题
4. **设备性能**：部分低端设备可能不支持 4K 硬解，需要降级到 1080P

## 总结

**不是 PlatformView 的问题**，你的项目已经使用了最优的 Texture 渲染方案。

4K 卡顿主要是因为：
1. ❌ 缓冲区太小（4MB 不够用）
2. ❌ 没有针对 4K 的特殊优化
3. ❌ 可能使用了 AV1 编码（解码性能要求高）

按照上述方案优化后，4K 播放应该会流畅很多！
