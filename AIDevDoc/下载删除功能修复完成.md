# 下载删除功能修复完成

## 问题描述

用户反馈：正在缓存的视频点击删除后仍然存在，无法正确删除。

## 问题分析

经过分析发现问题出现在 `cancelSpecificDownload` 方法中：

1. **删除逻辑不完整**：只处理了活动下载中的任务，没有处理等待队列中的任务
2. **UI更新不及时**：删除操作后UI没有立即刷新
3. **队列管理混乱**：删除操作后没有正确启动下一个下载

## 修复内容

### 1. 完善删除逻辑

**修复前的问题：**
```dart
Future<void> cancelSpecificDownload(int cid, {required bool isDelete}) async {
  final task = _activeDownloads[cid];
  if (task != null) {
    // 只处理活动下载中的任务
    await task.cancel(isDelete: isDelete);
    _activeDownloads.remove(cid);
    
    if (isDelete) {
      // 只从等待队列中移除，但可能任务根本不在活动下载中
      waitDownloadQueue.removeWhere((e) => e.cid == cid);
    }
  }
}
```

**修复后的逻辑：**
```dart
Future<void> cancelSpecificDownload(int cid, {required bool isDelete}) async {
  final task = _activeDownloads[cid];
  
  // 无论是否在活动下载中，都要从等待队列中移除（如果是删除操作）
  if (isDelete) {
    waitDownloadQueue.removeWhere((e) => e.cid == cid);
  }
  
  if (task != null) {
    await task.cancel(isDelete: isDelete);
    _activeDownloads.remove(cid);
    
    if (!isDelete) {
      // 暂停逻辑保持不变
      await _updateBiliDownloadEntryJson(task.entry);
      task.entry.status.value = DownloadStatus.pause;
      if (!waitDownloadQueue.any((e) => e.cid == cid)) {
        waitDownloadQueue.add(task.entry);
      }
    }
    
    // 清除当前下载状态
    if (curDownload.value?.cid == cid) {
      _curCid = null;
      curDownload.value = null;
    }
    
    // 启动下一个下载
    if (!isDelete) {
      _startNextDownload();
    }
  }
  
  // 如果是删除操作，启动下一个下载
  if (isDelete) {
    _startNextDownload();
  }
}
```

### 2. 修复的关键点

#### 优先处理等待队列
- **问题**：之前只有在活动下载中找到任务时才从等待队列移除
- **修复**：无论任务在哪里，删除操作都会先从等待队列中移除

#### 确保队列管理
- **问题**：删除后没有启动下一个下载
- **修复**：删除操作后总是尝试启动下一个下载

#### 状态清理
- **问题**：删除后可能留下无效的当前下载状态
- **修复**：正确清理 `curDownload` 状态

### 3. 删除操作的完整流程

1. **从等待队列移除**：如果是删除操作，立即从 `waitDownloadQueue` 中移除
2. **取消活动下载**：如果任务在活动下载中，取消下载并从 `_activeDownloads` 中移除
3. **清理状态**：清理相关的状态变量
4. **启动下一个**：启动等待队列中的下一个下载
