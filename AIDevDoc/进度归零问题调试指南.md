# 进度归零问题调试指南

## 问题现象
1. 下载视频A到30%，切换到视频B，视频A进度归零
2. 暂停所有视频后退出页面，重新打开进度都归零
3. 等待中的视频不显示已下载大小/总大小

## 已实施的修复

### 1. 进度保存策略
- ✅ 进度变化超过5MB时立即保存
- ✅ 每5秒自动保存一次
- ✅ 暂停时立即保存
- ✅ 切换视频时立即保存

### 2. UI显示优化
- ✅ 等待中的视频显示已有进度
- ✅ 统一按钮样式（都使用X图标取消）
- ✅ 区分正在下载和已暂停状态

### 3. 调试日志
添加了关键位置的调试日志：
- 读取JSON时打印进度
- 暂停时打印进度
- 切换视频时打印进度

## 调试步骤

### 步骤1：检查日志输出
运行应用后，在控制台查看日志：

```
读取条目 123456: downloaded=10485760, total=52428800, completed=false
```

如果看到 `downloaded=0, total=0`，说明JSON没有正确保存进度。

### 步骤2：测试切换视频
1. 开始下载视频A
2. 等待进度到30%
3. 点击视频B的"立即下载"
4. 查看控制台日志：
```
暂停视频 123456: 15728640/52428800
```
5. 查看视频A的UI，应该显示"已暂停 30%"

### 步骤3：检查JSON文件
1. 找到应用文档目录：`应用文档目录/downloads/`
2. 找到对应视频的 `entry.json` 文件
3. 打开查看 `total_bytes` 和 `downloaded_bytes` 字段
4. 应该看到非零值

### 步骤4：测试退出重进
1. 暂停所有下载
2. 查看控制台日志确认保存
3. 退出缓存页面
4. 重新进入缓存页面
5. 查看控制台日志：
```
读取条目 123456: downloaded=15728640, total=52428800, completed=false
```
6. UI应该显示正确的进度

## 可能的问题

### 问题1：JSON保存失败
**症状**：日志显示保存，但JSON文件没有更新

**检查**：
```dart
// 在 _updateBiliDownloadEntryJson 中添加日志
debugPrint('保存JSON: ${entry.cid}, ${entry.toJson()}');
```

**可能原因**：
- 文件权限问题
- 磁盘空间不足
- 异步操作未完成

### 问题2：JSON读取失败
**症状**：JSON文件有数据，但读取时为0

**检查**：
- `DownloadEntryInfo.fromJson()` 是否正确
- `RxInt` 初始化是否正确

### 问题3：UI不刷新
**症状**：数据正确，但UI显示为0

**检查**：
- `Obx` 是否正确包裹
- `waitDownloadQueue.refresh()` 是否调用
- `RxInt.value` 是否正确访问

## 临时解决方案

如果问题持续，可以尝试：

### 方案1：强制同步保存
```dart
void _onReceive(int progress, int total) {
  // 每次都保存（性能差但数据安全）
  entry.downloadedBytes.value = progress;
  _updateBiliDownloadEntryJson(entry);
}
```

### 方案2：增加保存频率
```dart
// 改为每1秒或1MB保存一次
if (progressDiff > 1 * 1024 * 1024) {
  _updateBiliDownloadEntryJson(entry);
} else {
  _progressSaveTimer = Timer(const Duration(seconds: 1), () {
    _updateBiliDownloadEntryJson(entry);
  });
}
```

### 方案3：添加内存缓存
```dart
// 在切换视频时，先从内存读取，而不是从JSON
final cachedEntry = waitDownloadQueue.firstWhereOrNull((e) => e.cid == cid);
if (cachedEntry != null) {
  // 使用内存中的数据
}
```
